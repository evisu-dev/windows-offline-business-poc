## 1. ダッシュボード

**パス:** `GET /`

**コントローラー:** `DashboardController`（Invokable）

**概要:** アプリケーションのトップページ。業務の概況を一目で把握できる。

**表示内容:**
- 顧客数
- 受注数
- 未着手件数
- 進行中件数
- クイック操作ボタン（顧客登録、受注登録、CSV出力、バックアップ）
- アプリバージョン・環境情報

---

## 2. 顧客管理

### 一覧画面
- **パス:** `GET /customers`
- **コントローラー:** `CustomerController@index`
- **表示項目:** ID、名前、電話番号、メール、操作ボタン
- **操作:** 新規登録、編集、削除、CSV出力、CSV取込
- **検索:** 顧客名で部分一致検索が可能（後述）

### 登録画面
- **パス:** `GET /customers/create`
- **コントローラー:** `CustomerController@create`
- **FormRequest:** `StoreCustomerRequest`
- **入力項目:**

| フィールド | 必須 | バリデーション |
|---|---|---|
| 名前 | ○ | 文字列、最大255文字 |
| 電話番号 | - | 文字列、最大50文字 |
| メール | - | メール形式、最大255文字 |
| 住所 | - | 文字列、最大1000文字 |
| 備考 | - | 文字列、最大2000文字 |

### 編集画面
- **パス:** `GET /customers/{customer}/edit`
- **入力項目:** 登録画面と同一

### 削除
- **パス:** `DELETE /customers/{customer}`
- **確認:** JavaScript confirmダイアログ
- **注意:** 紐づく受注もカスケード削除される

---

## 3. 顧客検索

- **パス:** `GET /customers?q={検索文字列}`
- **コントローラー:** `CustomerController@index`
- **検索対象:** 顧客名（`name`カラム）
- **検索方式:** 部分一致（LIKE `%keyword%`）
- **パラメータ:**

| パラメータ | 必須 | 説明 |
|---|---|---|
| `q` | - | 顧客名の検索文字列 |

- `q`未指定時は全件表示
- 該当なしの場合「検索条件に一致する顧客がありません。」を表示
- GETフォームで送信、クリアボタンでリセット

---

## 4. 顧客CSV出力

- **パス:** `GET /customers/export/csv`
- **コントローラー:** `CustomerExportController@csv`
- **ファイル名:** `customers_YYYYMMDD.csv`
- **文字コード:** BOM付きUTF-8（Excel対応）
- **カラム:**

| 列順 | カラム名 |
|---|---|
| 1 | 名前 |
| 2 | 電話番号 |
| 3 | メール |
| 4 | 住所 |
| 5 | 備考 |

- IDは含めない（CSV取込との往復利用を考慮）
- 全件出力（検索条件は連動しない）

---

## 5. 顧客CSV取込

- **画面パス:** `GET /customers/import`
- **処理パス:** `POST /customers/import`
- **コントローラー:** `CustomerImportController`

### 対応フォーマット

| 項目 | 値 |
|---|---|
| 文字コード | UTF-8 / UTF-8 BOM付き |
| 区切り | カンマ |
| ヘッダ | 必須（1行目） |
| 最大ファイルサイズ | 10MB |

### 期待ヘッダ

```text
名前,電話番号,メール,住所,備考
```

### バリデーションルール

顧客登録（`StoreCustomerRequest`）と同一のルールを適用:
- 名前: 必須、文字列、最大255文字
- 電話番号: 任意、文字列、最大50文字
- メール: 任意、メール形式、最大255文字
- 住所: 任意、文字列、最大1000文字
- 備考: 任意、文字列、最大2000文字

### エラー処理

- **ヘッダ不正:** 取込を拒否し、期待する列名を表示
- **行バリデーションエラー:** 何行目に何のエラーがあるかを一覧表示
- **トランザクション:** 全件成功または全件失敗（1行でもエラーがあれば0件登録）
- **空行:** 全列空の行はスキップ

### 重複データ

顧客の一意キーは定義されていないため、同名顧客が存在しても重複排除は行わない。

### CSVラウンドトリップ

顧客CSV出力で出力したCSVをそのまま顧客CSV取込で取り込める互換性を保証する。

## 6. 受注管理

### 一覧画面
- **パス:** `GET /work_orders`
- **コントローラー:** `WorkOrderController@index`
- **表示項目:** ID、顧客名、件名、ステータス（バッジ表示）、納期、操作ボタン
- **操作:** 新規登録、編集、削除、PDF出力、CSV出力
- **検索:** 件名・ステータス・顧客で絞り込み可能（後述）

### 登録画面
- **パス:** `GET /work_orders/create`
- **コントローラー:** `WorkOrderController@create`
- **FormRequest:** `StoreWorkOrderRequest`
- **入力項目:**

| フィールド | 必須 | バリデーション |
|---|---|---|
| 顧客 | ○ | customersテーブルに存在する値 |
| 件名 | ○ | 文字列、最大255文字 |
| 詳細 | - | 文字列、最大5000文字 |
| ステータス | ○ | `WorkOrder::STATUSES` のいずれか |
| 納期 | - | 日付形式 |

### ステータス値

モデル定数 `WorkOrder::STATUSES` で定義:

| 値 | 説明 |
|---|---|
| 未着手 | 登録直後のデフォルト状態 |
| 進行中 | 作業開始済み |
| 完了 | 作業完了 |
| キャンセル | 取り消し |

### 編集画面
- **パス:** `GET /work_orders/{work_order}/edit`
- **入力項目:** 登録画面と同一

### 削除
- **パス:** `DELETE /work_orders/{work_order}`
- **確認:** JavaScript confirmダイアログ

---

## 7. 受注検索・絞り込み

- **パス:** `GET /work_orders?q={キーワード}&status={ステータス}&customer_id={顧客ID}`
- **コントローラー:** `WorkOrderController@index`
- **検索方式:** 条件はAND結合

| パラメータ | 必須 | 対象 | 方式 |
|---|---|---|---|
| `q` | - | 件名（`title`） | 部分一致 |
| `status` | - | ステータス | 完全一致（`WorkOrder::STATUSES`に含まれない値は無視） |
| `customer_id` | - | 顧客ID | 完全一致 |

- 全パラメータ未指定時は全件表示
- 該当なしの場合「検索条件に一致する受注がありません。」を表示
- GETフォームで送信、クリアボタンでリセット
- 検索フォーム内に顧客セレクトボックス・ステータスセレクトボックスを配置

## 8. 受注CSV出力

- **パス:** `GET /work_orders/export/csv`
- **コントローラー:** `WorkOrderExportController@csv`
- **ファイル名:** `work_orders_YYYYMMDD.csv`
- **文字コード:** BOM付きUTF-8（Excel対応）
- **カラム:** ID、顧客名、件名、ステータス、納期、登録日
- 全件出力（検索条件は連動しない）

## 9. 作業指示書PDF出力

- **パス:** `GET /work_orders/{work_order}/pdf`
- **コントローラー:** `WorkOrderExportController@pdf`
- **ファイル名:** `work_order_{id}.pdf`
- **用紙:** A4縦
- **内容:**
  - 受注番号、顧客名、件名、ステータス、納期、登録日、詳細
  - 顧客の電話番号・住所（存在する場合）
  - 出力日時

**日本語フォント:**
- IPAexゴシックを使用（`php artisan pdf:setup-font` で導入）
- フォント未導入時もPDF生成は可能（日本語が文字化けする場合あり）

## 10. バックアップ・復元

- **パス:** `GET /backup`
- **コントローラー:** `BackupController`

### バックアップ（ダウンロード）
- **パス:** `GET /backup/download`
- **動作:** SQLiteデータベースファイルをそのままダウンロード
- **ファイル名:** `backup_YYYYMMDD_HHmmss.sqlite`

### 復元（リストア）
- **パス:** `POST /backup/restore`
- **入力:** SQLiteファイルのアップロード（最大50MB）
- **検証:**
  1. SQLiteマジックナンバー（`SQLite format 3`）の確認
  2. ファイルベースDB接続の確認（`:memory:`では不可）
  3. 復元後に`customers`、`work_orders`テーブルの存在を検証
  4. `migrations`テーブルが空でないことを確認
- **安全策:**
  - 復元前に現在のDBを自動退避（`.bak.YYYYMMDDHHmmss`）
  - 検証失敗時は退避ファイルから自動ロールバック
