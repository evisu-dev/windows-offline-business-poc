# セキュリティ・制約事項

## セキュリティ対策

### CSRF保護

全POSTリクエストにLaravelのCSRFトークン検証を適用。Bladeテンプレートで `@csrf` ディレクティブを使用。

### 入力バリデーション

| 機能 | 対策 |
|---|---|
| 顧客登録・更新 | 各フィールドの型・最大長を検証 |
| 受注登録・更新 | ステータス値を `Rule::in()` で許可リスト制限 |
| 顧客CSV取込 | ヘッダー検証 + 各行バリデーション + エラー時全件ロールバック |
| バックアップリストア | SQLiteマジックナンバー検証 + テーブル存在確認 + マイグレーション整合性チェック |

### XSS対策

Bladeの `{{ }}` 構文により全出力が自動エスケープ。

### SQLインジェクション対策

Eloquent ORM / クエリビルダーによるパラメータバインディングを使用。生SQLの直接実行なし。

### ファイルアップロード

- 顧客CSV取込: ファイルアップロードを許可
  - 最大1MB
  - CSVヘッダー検証（必須列: `名前`）
  - 各行バリデーション（メール形式、最大長等）
  - エラー時に全件ロールバック
- バックアップリストア: ファイルアップロードを許可
  - 最大50MB
  - SQLiteヘッダーのバイナリ検証
  - 必須テーブル存在確認
  - マイグレーション整合性チェック
  - 復元失敗時の自動ロールバック

## 制約事項

### オフライン前提

- 外部APIへの依存なし
- CDNからのリソース読み込みなし
- PDF用フォントは事前にローカルへ配置が必要

### 単一ユーザー

- 認証・認可機能は未実装
- 同時アクセス制御なし（デスクトップアプリとして単一プロセスで動作）

### データ保護

- `.env` ファイルはGit管理外
- バックアップファイルは暗号化されていない（SQLite平文）
- 本番環境では `APP_DEBUG=false` に設定すること

### NativePHP固有の制約

- macOS 12以上が必要（開発環境）
- Windows 11 x64 が必要（ビルド・配布）
- PHP/Node.jsは NativePHP がバンドルするため、エンドユーザーへの個別インストールは不要

## 既知の制限

| 項目 | 説明 | 対応方針 |
|---|---|---|
| PDF日本語フォント | IPAexゴシック未導入時に文字化け | `pdf:setup-font` コマンドで解消 |
| バックアップ暗号化 | SQLiteファイルが平文 | 将来的にAES暗号化を検討 |
| 同時書き込み | SQLiteの書き込みロック | 単一ユーザー前提で問題なし |
| テストカバレッジ | バックアップ復元のハッピーパスが`:memory:`でスキップ | ファイルベースDBのテスト環境を別途用意する |
